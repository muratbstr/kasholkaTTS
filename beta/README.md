# kasholkaTTS Beta 1.7.3 Beta 1

Отдельная экспериментальная версия на основе kasholkaTTS 1.7.2 Release 2.
Устанавливается как `~/Applications/kasholkaTTS Beta.app`, использует отдельный
идентификатор `com.kasholka.tts.beta` и отдельные настройки. Основная версия
остаётся установленной. Иконка — тот же силуэт и скруглённые углы, фон `#0040ff`.

## Установка

Распакуйте весь архив на Mac с macOS Monterey 12 или новее и запустите
`Install kasholkaTTS Beta.command`. Для обновления завершите только Beta через ⌘Q.
Установщик собирает приложение встроенным `osacompile`, без sudo и загрузок.
Ранее установленная Beta сохраняется в отдельную папку резервной копии.
Это локальная подпись, а не нотарификация Apple; Windows этот установщик не запускает.

В начале установщик предлагает **Русский / English** и отмену, затем показывает
только этапы установки. При автообновлении используется язык Beta или macOS без диалога.
Явный выбор без окна: `--lang ru` / `--lang eng`. При ошибке показывается
путь к техническому журналу.

Меню **kasholkaTTS Beta → Обновления** проверяет выпуски GitHub,
загружает и устанавливает новую Beta с подтверждением перезапуска. Основная версия
не заменяется. Проверка при запуске отключается в этом же меню. Текст и выделение
восстанавливаются после обновления; старая Beta сохраняется как резервная копия.
Первый переход с 1.5.1 Beta 1 — вручную. Сборка 1.7.3 пока подготовлена только локально.

**kasholkaTTS Beta → Язык / Language** переключает русский и английский интерфейс
или выбирает язык по macOS. Выбор применяется при следующем запуске и не зависит
от основной версии. Меню и сообщения экспериментов Beta также переведены.

## Что попробовать для Siri на Monterey 12.6.5

Сначала в **Системные настройки → Универсальный доступ → Устный контент** выберите
скачанный Siri как системный голос. Выбор голоса в настройках самого ассистента
Siri — отдельная настройка. Проверьте звучание системной кнопкой воспроизведения.

1. **Beta → Siri через «Устный контент»…** — основной практический вариант для Monterey.
   Включите системную функцию «Проговаривать выбранный текст». Команда подготовит
   выделение в редакторе: если ничего не выделено, выделится весь текст.
   Нажмите системное сочетание, обычно **⌥Esc**. Читает сама macOS выбранным в её
   настройках голосом, а не речевой движок приложения. Остановить — повторным
   сочетанием или системной панелью. Кнопки приложения, его темп, высота и экспорт
   не управляют этим чтением. Перед обычным чтением остановите системное, чтобы
   они не звучали одновременно. Beta не отправляет искусственные нажатия клавиш.
2. **Beta → Проверить Siri ID из настроек** — новый эксперимент с прямым обращением
   по фактическим идентификаторам вместо одного перечисления голосов. Отдельный
   процесс читает голосовые настройки `com.apple.Accessibility` и
   `com.apple.speech.voice.prefs`, проверяет найденные Siri ID и голоса по языкам
   `ru-RU`, `en-US`, `en-GB`. Подменённые ID и обычные голоса не выдаются за Siri.
   Доступные Siri ID добавляются в обычный список как `[Siri]`; чтение идёт через
   тот же osascript. Проверка ограничена 20 секундами и отменяется кнопкой «Стоп».
   Отсутствие ID в этих настройках не означает, что Siri не скачаны.
   Успешное создание объекта голоса ещё не доказывает, что звук будет Siri:
   сравните «Прослушать» с системной пробой. Экспорт таких голосов сохраняет
   прежнее ограничение: требуется Swift/Command Line Tools, и голос может быть
   недоступен этому помощнику.
3. **Beta → Прочитать системным say…** — отдельная проверка системного голоса без
   параметра `-v`. Голос и темп берутся из macOS, текст — из редактора или выделения.
   «Стоп» прерывает только наш процесс; паузы, подсветки и экспорта в этом режиме нет.
   Для Monterey опубликован отрицательный результат, поэтому этот путь оставлен
   именно для сравнения, а не как обещанное решение. Код выхода 0 не подтверждает Siri.
4. Прежний **Дебаг → Поиск голосов Siri** проверяет обычное перечисление через
   osascript и интерпретируемый Swift. Он сохранён отдельно от новых опытов.

**Beta → Отчёт экспериментов…** копирует версии, найденные ID, фактические ответы
API и ошибки. Текст редактора не включается. Отчёт находится в памяти до выхода.
Настройки системных голосов читаются, но не изменяются. Приложение не патчит
системные библиотеки, не отключает SIP и не устанавливает драйверы.

Доступность Siri внутри списка приложения на 12.6.5 **не подтверждена**. В отчётах
пользователя обычная версия уже получала 77 голосов и 0 Siri через три пути.
Beta проверяет другие варианты, но не снимает ограничения macOS.

## Источники исследования, 25 октября 2026

- [Apple, WWDC20: Create a seamless speech experience](https://developer.apple.com/videos/play/wwdc2020/10022/):
  Siri из Spoken Content недоступны обычному AVSpeechSynthesizer; возможна подмена.
- [Apple: voiceWithIdentifier](https://developer.apple.com/documentation/avfaudio/avspeechsynthesisvoice/init(identifier:)):
  получение голоса по ID. Проба прямых ID из настроек — наш эксперимент, Apple не
  документирует его как способ открыть Siri.
- [Проверка say на Ventura и Monterey автором ответа](https://stackoverflow.com/questions/61122378/make-the-say-terminal-utility-and-nsspeechsynthesizer-work-with-siri-voices/62680596):
  системный голос срабатывал на Ventura 13.0.1, на Monterey 12.0.1 — подмена.
- [Tobias Hagemann: Unlocking Siri Voices on macOS](https://tobiha.de/2026/02/14/unlocking-siri-voices-on-macos/):
  описание ключа `SpokenContentDefaultVoiceSelectionsByLanguage`, проверено автором
  на Tahoe. В Beta используется только чтение голосовых настроек, без предложенного
  в статье изменения системного языка.
- [Apple: проговаривание текста на экране](https://support.apple.com/guide/mac-help/mh27448/mac):
  системное выделение, сочетание клавиш и управление чтением.
- [siri-say, объяснение интерпретируемого Swift](https://github.com/marcomontalbano/siri-say):
  подход уже был реализован в основной версии и не дал Siri на Mac пользователя;
  повторное использование этого приёма не считается новым решением.

## Сборка и проверка

`python scripts/build_beta.py` создаёт отдельный ZIP и SHA-256, не меняя стабильный
архив, исходник или VERSION. Beta состоит из базового исходника и
`beta/experiments.js`; `beta/probe.js` работает отдельно. Формирование установщика
проверяет точки замены и отдельные пути/идентификатор.

Иконка: `python -c "from scripts.build_icon import build_icon; build_icon('beta/assets', (0, 64, 255))"`.
Скругление и силуэт строятся тем же ранее одобренным программным способом.

Проверки: `python -m unittest discover -s tests -v`. Нативные Mac-проверки на Windows
пропускаются. Пошаговая проверка Beta: `MAC_SMOKE_TEST.txt` в архиве.
Описание базовых возможностей: `STABLE_README.txt` (его указания имени/установки относятся к основной версии).
