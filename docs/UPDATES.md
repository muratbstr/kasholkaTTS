# Обновления kasholkaTTS: протокол 1

Обновлятор появился в 1.6.0 Release 1 / 1.6.1 Beta 1. Первая установка этих версий —
вручную. Эта работа не публикует релизы: сборки отправляются на GitHub только по
отдельной команде владельца проекта.

## Источник и формат выпуска

- Только публичный репозиторий `muratbstr/kasholkaTTS`, HTTPS, без токенов.
- [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#list-releases):
  страницы по 100 выпусков, максимум 10 страниц. Превышение лимита сообщает об ошибке.
- Stable: тег `v1.6.0`, не prerelease, файл `kasholkaTTS-1.6.0-Release-1-macOS-installer.zip`.
- Beta: тег `v1.6.1-beta.1`, prerelease, файл `kasholkaTTS-Beta-1.6.1-Beta-1-macOS-installer.zip`.
- Рядом обязателен файл `<имя ZIP>.sha256`, создаваемый сборщиком. Оба asset должны
  иметь `state: uploaded`. Версия тега, имя ZIP и файл VERSION должны совпадать.
- [Ссылки assets](https://docs.github.com/en/rest/releases/assets#get-a-release-asset)
  принимаются только из `https://github.com/muratbstr/kasholkaTTS/releases/download/<tag>/`.
  HTTPS-перенаправления на хранилище GitHub разрешены. Пользовательский `.curlrc` отключён.
- Если GitHub прислал digest SHA-256, он также проверяется. Проверка SHA-256 защищает
  от повреждения файла; независимой подписи обновлений/нотарификации здесь нет.
  Владельцы репозитория и опубликованный ими код входят в модель доверия.

Выбирается максимальная **числовая** версия своего канала, а не последний по дате тег.
Идентификаторы bundle, настройки, имена приложений и резервные копии каналов разделены.
Для публикации сначала загружаются все четыре assets (два ZIP и две SHA-256)
в черновик, и только потом публикуется релиз.

## Раздельные архивы и счётчик

Начиная с 1.7.4 Release 2.2 / 1.7.5 Beta 1 сборщики создают две пары файлов:

| Назначение | Окончание имени | Новый счётчик |
| --- | --- | --- |
| Ручная установка | `-macOS-manual-installer.zip` + `.sha256` | Только ZIP |
| Автообновление | `-macOS-installer.zip` + `.sha256` | Не учитывается |

Старое имя сохранено у автоматического архива намеренно: выпущенная 1.7.2 и другие
клиенты протокола 1 уже ищут его. Ручной ZIP не выбирается обновлятором. Однако старые стабильные клиенты не распознают
Release 2.2: переход с 1.7.2 на этот выпуск выполняется вручную. Новая политика сравнивает
компоненты Release численно (2.10 > 2.2); формат Beta 1 сохраняется.
У обоих ZIP одинаковые файлы приложения и ресурсов, но разные корневые папки,
совпадающие с именем соответствующего ZIP без расширения; контрольные суммы различаются.
Архивы нельзя просто переименовывать: это нарушит проверку корня обновлятором.

В черновик релиза загрузить оба ZIP и обе контрольные суммы. В описании релиза,
README и прямых ссылках для пользователей указывать `-macOS-manual-installer.zip`.
У служебного ZIP желательно поставить label «Для автообновления / Automatic updates».
Версии, теги и содержимое VERSION должны совпадать. Проверить обе SHA-256 после загрузки.
Опубликовать новый workflow счётчика вместе с этими изменениями; затем запустить его вручную.
Бейдж остаётся по прежнему адресу `badges/downloads.json`; дополнительных токенов нет.

Счётчик суммирует только полностью загруженные ручные assets всех опубликованных
релизов, включая Beta. Старые общие ZIP исключаются, потому что их download_count
не позволяет отделить обновления от ручных загрузок. Поэтому отсчёт начинается заново. [Инструкция по последующим сбросам](DOWNLOAD_COUNTER.md).
Счётчик различает файлы, а не источник запроса: ручное скачивание служебного ZIP
тоже исключается, а скачивание ручного ZIP любой программой учитывается.
Это не число установок и не число уникальных пользователей.

Проверки совместимости с опубликованной политикой 1.7.2 и обоих комплектов ZIP:
`python -m unittest discover -s tests -v`.

## Проверка при запуске

Если «Проверять при запуске» включено (по умолчанию), после закрытия экрана загрузки
приложение запускает одну фоновую проверку GitHub за запуск. Повторный callback
не создаёт вторую проверку. Успешная ручная проверка, недавний запуск или старое
значение updateLastCheck больше не откладывают её на сутки. Отключение настройки
сохраняется; ручная команда продолжает работать независимо от неё.

Начало и результат без новой версии видны в строке состояния, пока приложение
не занято речью/экспортом/поиском голосов. При отсутствии обновления автоматический
запрос не открывает модальное окно. Предложение найденного обновления ждёт окончания
работы; ошибка сети оставляет приложение доступным и не подавляет проверку следующего запуска.

## Установка и данные

1. `curl` работает в отдельном NSTask. Интерфейс опрашивает его таймером, без ожидания
   в главном потоке. Максимум 180 секунд на сетевой запрос, 128 МиБ на архив.
2. SHA-256 сравнивается системным `shasum`. Список ZIP проверяется на чужой корень,
   повторы, управляющие символы и переходы `..`. `unzip -p` копирует только фиксированный
   список файлов в заранее созданные каталоги. Пути и символические ссылки из ZIP
   никогда не используются как пути назначения. Размер и время извлечения ограничены.
3. Скачанный установщик должен иметь маркер `# kasholka-update-protocol: 1` и принимать
   `--update`: та же сборка, подпись и резервное копирование, но без финального диалога.
   Список обязательных файлов задаёт `updatePackageFiles()`; новые обязательные ресурсы
   требуют совместимого расширения протокола, а не только добавления файла в ZIP.
4. Пользователь подтверждает перезапуск. Работает только обновление приложения в
   `~/Applications` с ожидаемым именем. Помощник сначала подтверждает запуск, затем
   приложение сохраняет текст и выделение и штатно завершает работу.
5. Помощник ждёт завершения конкретного PID до 60 секунд, запускает установщик,
   проверяет bundle ID и версию и открывает приложение. Если сборка не удалась,
   открывается оставшаяся старая версия. Замена выполняется после успешной сборки
   и подписи; установщик повторно проверяет, что приложение не запущено.

Все задания имеют случайный каталог `kasholka-update-<UUID>` в пользовательском
`NSTemporaryDirectory()` с правами 0700. В настройках сохраняется только путь к
снимку редактора; сам текст — в `resume.json` внутри этого каталога. После успешного
восстановления текст удаляется. При сбое остаются журнал/файлы для диагностики;
после аварийного завершения могут остаться и временные данные. Это не история текстов
и не долговременное резервное копирование: macOS может очистить временный каталог.

Отмена завершает только собственный NSTask. Каталог не удаляется, пока процесс ещё
пишет в него. При закрытии приложения во время загрузки файлы могут остаться во
временной папке; установки после такого закрытия не происходит.

## Проверки

`python -m unittest discover -s tests -v` проверяет правила выбора, разделение каналов,
неверные URL, неполные загрузки, SHA-256, ZIP, тайм-ауты, отмену, ожидание чтения,
рукопожатие с помощником и сохранение/восстановление текста с UTF-16 диапазонами.
На Mac дополнительно проверяются настоящий NSTask/Foundation, извлечение тестового
ZIP, синтаксис Bash и компиляция обоих приложений через osacompile.

Перед публикацией проверить на Monterey 12.6.5:

1. Запуск без сети и ручную проверку с отключённой сетью: читалка остаётся работоспособной.
2. Включить автопроверку, запустить приложение дважды подряд (между запусками ⌘Q).
   Каждый запуск показывает проверку; при отсутствии нового выпуска — статус актуальной версии.
   Повторить после ручной проверки и без сети. Затем выключить автопроверку: следующий
   запуск не делает запроса, но ручная команда по-прежнему работает.
3. Когда будет опубликован следующий выпуск: предложение только своего канала,
   скачивание, отмену и повторный запуск проверки. Чтение/экспорт не прерываются.
4. Установку из `~/Applications`: текст с кириллицей/эмодзи и выделением возвращается,
   версия меняется, старая сборка остаётся рядом. Приложение из другой папки предлагает
   запустить нужную копию вместо замены постороннего пути.
5. Недостаток прав записи/места и повторное открытие приложения во время сборки:
   ошибка не должна уничтожать прежнюю сборку; журнал остаётся доступен.
6. Успешное обновление и ошибку отдельно у Beta: основная версия не затрагивается.

Полный сценарий скачивания опубликованного следующего релиза и перезапуска на Mac
в среде Windows проверить нельзя; его нельзя считать пройденным по этим тестам.
